# 2. Global Architecture Overview

## 2.1 High-Level System Architecture

The project implements a highly scalable and observable microservices architecture deployed on **Amazon Web Services (AWS)** using a managed container orchestration strategy.

### Cloud & Orchestration
*   **AWS (Cloud Provider)**: Provides the global infrastructure. We utilized **Amazon EKS (Elastic Kubernetes Service)** as the control plane to manage the lifecycle of our containers.
*   **Managed Nodes**: The cluster runs on **EC2 t3.small** instances. Due to the limited RAM (2GB per node), the system was designed in "Budget-Survival Mode," utilizing aggressive resource limits and staggered deployments.

### CI/CD Pipeline
*   **Jenkins**: Orchestrates the entire delivery lifecycle. Jenkins is deployed within the cluster and manages:
    *   **Source Control**: Pulling code from GitHub.
    *   **Build Engine**: Utilizing **Kaniko** to build Docker images without requiring a Docker daemon (Docker-in-Docker), which is more secure and resource-efficient in Kubernetes.
    *   **Registry**: Pushing verified images to **Docker Hub**.
    *   **Automated Deployment**: Rolling out updates to the microservices namespace.

### Monitoring & Logging
*   **Prometheus**: Acts as the central time-series database, scraping metrics from Spring Boot Actuator endpoints (`/actuator/prometheus`).
*   **Grafana**: Provides a visual dashboard for real-time monitoring of CPU, RAM, and Pod availability.
*   **AWS CloudWatch**: Integrated via a **CloudWatch Agent DaemonSet**. It streams container logs directly to AWS CloudWatch Logs, ensuring log persistence even if pods are recycled.
